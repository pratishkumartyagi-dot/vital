# Active Context: Vital Monitoring App (Next.js + MCD-rPPG)

## Current State

**Project Status**: ✅ Functional Next.js web app with MCD-rPPG training integration

The project is a research-grade PPG Vital Signs application built with Next.js 16. It includes a web-based vital monitoring page with real-time camera-based PPG signal processing, and a complete MCD-rPPG training pipeline integrated into the project for model training and evaluation.

(9) **skin-ROI sampling**: front mode averages only YCbCr skin-tone pixels (Cb 77-127, Cr 133-173, brightness 45-245, ≥5% coverage) with a "Skin ROI locked / Looking for skin..." badge; frames without skin are excluded from the analysis buffers (dead `detectFaceROI`/`roiDataRef` removed); - [x] **PPG pipeline correctness fix (BPM/HRV/SpO2/Hb) (2026-10-02)**: Root cause was the hardcoded "4th-order Butterworth" SOS in `ppg-analysis.ts` (introduced in `52d963c`), whose real passband was centred on **~0.5 Hz with ~13x (22 dB) gain** and attenuated 1.5-3.5 Hz by 6-24 dB — i.e. it passed respiration/baseline and suppressed the cardiac band. On synthetic PPG with known HR the old code returned 90→65.5 and 120→31.6 BPM and HRV in the thousands of ms; SpO2/Hb AC/DC ratios were computed on a respiration-dominated signal. Fixes: (1) replaced it with a correct **RBJ/BL-transformed 2nd-order Butterworth HP(0.5 Hz)+LP(3.5 Hz) cascade** (zero-phase filtfilt, valid at any `fs`) — now 50/60/72/90/110/130/150 BPM all within 0.2 BPM; (2) hardened `detectPeaks` threshold (p10/p90/p97 based) and made `analyzeHeartRate` accept peaks iteratively against the last accepted peak + reject ectopic RR (>30% from median) before HRV, ending the 1000+ ms SDNN/RMSSD blow-ups; (3) gated red/green/blue buffers to the measuring phase (and finger-detect in rear mode) and reset **all** buffers at session start, so warm-up/non-finger/previous-session samples no longer contaminate AC/DC; (4) SpO2 switched from red/blue (which saturated) to the red/green ratio-of-ratios with the textbook `110 - 25*R` calibration (green is the highest-SNR channel; a red/green absorption ratio is the accepted contact-camera proxy), RMS-based AC, 30 s window, clamped [88,100], and now decoupled from HR validity; (5) fixed demo-mode synthetic PPG to advance a continuous phase clock (previously phase reset every frame → 10 Hz artifact hid the 72 BPM fundamental). Added `scripts/ppg-selfcheck.ts` (`bun run test:ppg`) as a regression guard. `bun typecheck`, `bun lint`, `bun run build`, `bun run test:ppg` all pass.

## Current Focus

The application is now a complete research platform for rPPG with:
1. **Web-based PPG Monitoring**: Real-time camera-based vital sign estimation (100s session: 10s warmup + 90s measurement) with signal quality reaching 100% for good smartphone camera PPG signals.
2. **Validation Dashboard**: Bland-Altman analysis with session management, measurement entry, and canvas-based plot visualization
3. **MCD-rPPG Training Pipeline**: Full training infrastructure for SCNN_8rois and other models
4. **Signal Processing**: FFT-based HR estimation, bandpass filtering, perfusion index calculation, multi-component SQI (perfusion index + spectral SNR + pulse regularity)
5. **Multi-ROI Extraction**: 5-region face ROI extraction for improved signal extraction
6. **Patient Intake**: Name, Age, Sex, Menopause status (if female, Yes/No), LMP (if non-menopausal female), Pregnancy status before measurement
7. **Heart Rate + HRV**: Peak-detection-based HR, RR-interval HRV (SDNN/RMSSD/pNN50), rhythm regularity
8. **Respiratory Rate**: Autocorrelation + FFT fusion in 0.1–0.5 Hz band, browser-native
9. **Database Persistence**: SQLite with Drizzle ORM for readings and validation data
10. **Serum Creatinine (research estimate)**: PPG/rPPG morphology-driven creatinine surrogate (Sridevi et al. 2025) with CKD-EPI 2021 eGFR + KDIGO staging, mode-specific normalization bands (no age term — age only re-enters via CKD-EPI), confidence caps (0.8 rear / 0.55 front), and SQI ≥ 40 gating, and validation-dashboard comparison against lab ground truth (±0.3 mg/dL). Labeled *not a substitute for a blood test*.
11. **Signal-quality gating everywhere**: composite SQI (perfusion + raw-signal spectral SNR + pulse regularity, pulse-presence gated) gates creatinine (≥40), glucose (≥50; not measurable from RGB alone), and SpO2/Hb (≥60). Front camera analyzes the POS chrominance pulse over skin-tone ROIs; rear camera uses center-ROI green with finger gating.

## Technical Specifications

- **Framework**: Next.js 16 + React 19 + TypeScript
- **Styling**: Tailwind CSS 4
- **Signal Processing**: FFT-based HR estimation (0.5-3.5 Hz bandpass)
- **Analysis Module**: `src/app/vital-monitoring/ppg-analysis.ts` — HeartPy-style peak detection + HRV (SDNN/RMSSD/pNN50) + RRest-style respiratory rate (autocorr/FFT fusion) + POS chrominance pulse (`posPulse`, Wang et al. 2017) + Hann-windowed `powerSpectrum` + creatinine morphology features (`extractCreatinineFeatures`/`estimateCreatinine`, age-term-free with mode-specific bands and SQI ≥ 40 gate) with CKD-EPI 2021 eGFR (`estimateEgfr`) and KDIGO staging (`kdigoStage`); DC-seeded `butterworthBandpass` (no filtfilt edge transient)
- **Python Reference**: `training/ppg_analysis.py` using `heartpy` + `RRest` for offline validation
- **Model**: SCNN_8rois (1D CNN with attention over 8 ROIs)
- **Training**: PyTorch with 5-fold cross-validation
- **Dataset**: MCD-rPPG (600 subjects, multi-camera)
- **Package Manager**: Bun
